Publishing

Every document, spec, report, plan, or longer write-up goes up as a live webpage with a clean editorial layout and Redaction font for article bodies. Deliver the post link, not a file. A Google Doc can be a backup only.

Site: https://42techpacks.github.io/42-press/

  1. Write the article as Markdown with a date, slug, title, and date in its front matter.
  2. Add it to the site's posts. The post appears at its direct page and at the top of the index.
  3. Verify the live URL returns 200 and renders correctly, especially tables, before sending Milo the link.
Style rule

All blog documents read at a high-school level: short sentences, plain words, and no jargon unless the term is the thing. Keep spec numbers, product names, and recommendations exact.

Status refresh

The Status tab is a clean list of Instinct's tasks for Milo. Whenever tasks start, complete, block, unblock, or change state, update the list right away. Do not batch lifecycle changes.

Status labels

Status rows use the actual product, file, or task names. Be specific. Use “Raglan Sleeve Striped Polo V2,” never “Latest tech pack review.” Show Instinct's tasks, not production tracker statuses.

Brevity rule

Articles are brief on top of plain: cut filler, use short sections, and keep facts, specs, and recommendations. The Status tab is a single-column task list with state tags.

Mobile previews

Show mockups and previews at mobile size first. Use desktop only when Milo asks.
